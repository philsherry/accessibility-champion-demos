# Dark Mode Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a 3-state (System default / Light / Dark) colour-scheme toggle to all 5 demo pages, with every colour on screen adapting correctly, verified by axe-core, visual regression, and a cross-page persistence test.

**Architecture:** CSS custom properties in `tokens.css` gain dark-mode values via `@media (prefers-color-scheme: dark)` (system default) and `:root[data-user-color-scheme="dark|light"]` (explicit override, wins on specificity). A blocking `theme-init.js` in `<head>` applies any stored preference before first paint. A `theme.js`, loaded on every page, wires a `<fieldset>` radio group in the header to `localStorage` + the attribute. Getting every page's *existing* hardcoded colours onto tokens first is a prerequisite — anything not a custom property can't switch with the theme.

**Tech Stack:** Plain HTML/CSS/JS (no framework, no build step), Playwright + `@axe-core/playwright` for tests, stylelint/eslint/prettier/djlint for linting.

## Global Constraints

- CSS class names: kebab-case, optional `--modifier` suffix (stylelint `selector-class-pattern` in `stylelint.config.js`) — e.g. `theme-toggle`, `theme-option`, not `theme-toggle__option`.
- Visually-hidden text uses the existing `.sr-only` utility class (`public/assets/css/base.css:695`) — not a new `.visually-hidden` class.
- Inline SVG icons use the existing `.icon` class (`public/assets/css/base.css:712`), which sets `fill:none; stroke:currentcolor; stroke-width:2; stroke-linecap:round; stroke-linejoin:round` — icon markup itself carries no inline stroke/fill attributes, only `viewBox` and shape elements, matching the existing cart icon.
- Touch targets: `var(--target-min)` (44px), same as every other interactive header element.
- `public/assets/js/*.js` files are plain classic scripts (`sourceType: 'script'` in `eslint.config.js`), not ES modules — no `import`/`export`, `var`/`function` style matching `cart.js`.
- CSS colour functions use modern space-separated syntax (`rgb(0 0 0 / 15%)`, `rgb(var(--x-rgb) / 15%)`), not comma syntax — stylelint enforces this.
- Test locators follow `CONVENTIONS.md`: accessible role/label first, `data-testid`/`data-component` only when no accessible name distinguishes siblings.
- Every new/edited CSS file must stay `stylelint` and `prettier --check` clean; every new/edited JS file must stay `eslint` clean; run `npm run lint` before each commit that touches CSS/JS.
- `npm test` (Playwright, non-visual) must stay green after every task from Task 6 onward.

### Task 8: `assets/js/theme-init.js` — no-flash init script

**Files:**
- Create: `public/assets/js/theme-init.js`

**Interfaces:**
- Consumes: `localStorage.getItem('theme')` (values `'auto'|'light'|'dark'`, written by Task 9's `theme.js`).
- Produces: `data-user-color-scheme` attribute on `<html>`, applied synchronously before first paint.

- [ ] **Step 1: Write the script**

```javascript
// Applies a stored colour-scheme preference before first paint, so the
// page never flashes the wrong theme. Loaded as a blocking <script> in
// <head>, before the stylesheet <link>s — see theme.js for the toggle
// that writes localStorage in the first place.
(function () {
  try {
    var stored = localStorage.getItem('theme');
    if (stored === 'light' || stored === 'dark') {
      document.documentElement.setAttribute('data-user-color-scheme', stored);
    }
  } catch (e) {
    // localStorage unavailable (private browsing, disabled storage) —
    // falls through to the @media (prefers-color-scheme) default.
  }
})();
```

### Task 9: `assets/js/theme.js` — toggle wiring script

**Files:**
- Create: `public/assets/js/theme.js`

**Interfaces:**
- Consumes: a `[data-component="theme-toggle"]` fieldset containing `<input type="radio" name="theme" value="auto|light|dark">` — produced by Task 10's HTML markup on every page.
- Produces: `data-user-color-scheme` attribute updates + `localStorage.setItem('theme', ...)` on change; syncs the checked radio to the current attribute state on page load.

- [ ] **Step 1: Write the script**

```javascript
// Wires every page's theme-toggle fieldset (see theme-init.js for the
// blocking script that applies a stored choice before first paint).
document.addEventListener('DOMContentLoaded', function () {
  var toggle = document.querySelector('[data-component="theme-toggle"]');
  if (!toggle) return;

  var radios = toggle.querySelectorAll('input[name="theme"]');
  var current = document.documentElement.getAttribute('data-user-color-scheme') || 'auto';

  radios.forEach(function (radio) {
    radio.checked = radio.value === current;

    radio.addEventListener('change', function () {
      if (radio.value === 'auto') {
        document.documentElement.removeAttribute('data-user-color-scheme');
        try {
          localStorage.removeItem('theme');
        } catch (e) {
          // localStorage unavailable — theme reverts to auto next load anyway.
        }
      } else {
        document.documentElement.setAttribute('data-user-color-scheme', radio.value);
        try {
          localStorage.setItem('theme', radio.value);
        } catch (e) {
          // localStorage unavailable — choice won't persist across reloads,
          // but still applies for the rest of this page view.
        }
      }
    });
  });
});
```
